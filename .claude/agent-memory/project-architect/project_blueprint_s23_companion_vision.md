Ish's long-term vision (private persistent personal AI on-device, stable identity,
learns its human + environment over years, companion + autonomous assistant) is now
`CODEY_OS_MASTER_BLUEPRINT.md` **§23**, with §1.7 as pointer and §21's P6 given a
five-track dependency skeleton (A persistent presence, B human model, C identity &
relationship, D self-extension, E proactive initiation). Doc grew 2714 → 3346 lines.
No code changed.

**Why:** Ish stated it as the destination the architecture is aimed at, plus a same-day
clarification that it is an **expansion, not a replacement** — the existing
self-learning/controlled-self-improvement programme (bench/gate.py, trajectory,
model_registry, reflection_engine, performance_tracker, goal_engine,
auto_improvement_loop, capability_optimizer, skill_recombiner) is a core requirement and
must not be demoted or absorbed by "learning the human."

**How to apply:**
- §23.2.1's **seven coexisting learning systems** is the governing frame: a taxonomy,
  not a hierarchy. Systems 3-6 (task outcomes, strategies, capabilities, own
  performance) = existing planned work. Systems 1, 2, 7 (human, device, identity) = the
  additions. Never write language that reads as one absorbing the other.
- §23 is **additive**: P0 done, P1 in progress, ordering unchanged. Seven items were
  **promoted out** of the vision into phases already doing that work — WP2.1 gains
  READ/ACT/HIGH_IMPACT authority classes; new WP4.6/4.7/4.8 fix `core/preferences.py`
  and impose provenance. Promote-now is the highest-value output of a vision round.
- **Item 7 decided, not escalated:** capability-based authority = WP2.1's Action Gateway
  extended with a third class + a distinct READ regime (mediated/audited, not per-act
  confirmed). A second policy layer above the gateway would recreate §16.1's
  three-disjoint-surfaces problem.
- PolicyEngine / DecisionEngine / ModelManager / Kernel **do not exist** under those
  names — §23.4.1 has the analog table. Say so plainly (rule 12).
- P6 test applied: if an item could be handed to an implementer as written, it belongs
  in P1/P2/P4, not P6. Tracks + entry gates only.
